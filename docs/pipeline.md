# 端到端流程：每一步的输入、输出与验收门

> 本文件描述**一次实验怎么跑**。每一步的「口径」不在这里写（去 `data_contracts/`），本文件只写**流程与门**。

---

## 0. 三条不可动的纪律

| # | 纪律 | 落点 |
|---|---|---|
| 1 | **数据契约未确认前不启动建模** | 阶段 1 → 阶段 2 的门 |
| 2 | **对外数字只认独立复算产出**，审计脚本不复用建模阶段的函数 | `audit/audit_recompute.py` |
| 3 | **失败与被证伪的结果必须留档**，只报最好的一组视为未完成 | `experiments/registry.md` |

## 1. 阶段总览

```
① 立项（投研负责人）
   输入：一句话研究请求
   产出：可证伪假设（对象 / 时间窗 / 数据截止点 / 评价指标 / 成本假设 / 推翻条件 / 停止条件）
   ↓
② 数据契约（金融数据工程师）
   输入：①的假设
   产出：数据源准入结论 → 字段字典 → 时点规则 → 快照清单（sha256）
   门：每个源都有 URL / 抓取方式 / 许可 / 频率 / 限制；取不到的显式记缺
   ↓
③ 建模与复现（量化研究员）
   输入：②的快照与契约
   产出：metrics.json / metrics_table.csv / figures/
   门：先最小基线再迭代；不调参、不挑口径；口径敏感性全量报出
   ↓
④ 独立复算（模型风控审计）
   输入：③的产出 + 同一份快照
   产出：audit_findings.json（PASS / SUGGESTION / BLOCKING）
   门：blocking 未关闭不得进入正式结论
   ↓
⑤ 汇总（投研负责人）
   输入：①–④
   产出：研究备忘录（事实 / 推断 / 反证 / 失败项 / 限制）
```

**单体语义**：本仓库由一个 agent 按①→②→③→④→⑤顺序扮演全部角色。**职责分离靠"不复用函数、独立代码路径、独立数据源、判据先写死"保证**，不是靠跨 agent 隔离——这是与小队模式的真实差别，写在这里是为了不被误读成"审过了"。

## 2. 每步的命令与验收门

### 阶段 ② 取数

```powershell
python scripts/fetch_market_data.py --exp <EXP>
```

| 验收项 | 判据 |
|---|---|
| 每个源都试过，且**失败也有留痕** | manifest 里 `ok:false` 的条目保留 `error` 原文 |
| 先探活再放量 | 单一源的第一次调用只取 ≤5 行样例，确认字段名与单位后才取窗口 |
| 单次返回 >200 行必须切片 | 按 `start_date` / `end_date` / `symbol` 压到题面所需最小区间 |
| 快照有校验值 | 每个落盘文件有 sha256 写进 manifest，路径用**仓库相对** |
| 原始层只追加 | 快照 CSV 写盘后不改写 |

### 阶段 ③ 指标

```powershell
python scripts/build_analysis.py --exp <EXP>
```

| 验收项 | 判据 |
|---|---|
| 只用真实快照 | 不生成任何合成 / 随机数据 |
| 指标有定义 | 每个指标在 `metric_definitions.md` 里查得到 |
| 代理口径标注 | 用了代理（如 `turnover_proxy`）→ 指标表脚注 + 图注 + 正文三处都写明 |
| 口径敏感性全量 | 多套口径全部报出，不挑最优 |

### 阶段 ③ 配图

```powershell
python scripts/build_figures.py --exp <EXP>
```

| 验收项 | 判据 |
|---|---|
| 面板对齐门 | `figures/<EXP>/*.alignment.json` 的 verdict ∈ {PASS, NOT APPLICABLE} |
| 碰撞审计门 | `figures/<EXP>/*.collision-audit.json` 的 verdict ∈ {PASS, REVIEW REQUIRED} |
| REVIEW REQUIRED 必须目视复核并披露 | 不能静默放过 |
| 图号按引用顺序 | 图号递增顺序 = 正文引用顺序 |

### 阶段 ④ 独立复算

```powershell
python audit/audit_recompute.py --exp <EXP>
```

| 验收项 | 判据 |
|---|---|
| 不复用建模函数 | 审计脚本用 `csv` 直读 + 纯 Python 重算，**不 import** `build_analysis.py` |
| 快照防漂移 | 逐个重算 sha256 与 manifest 比对 |
| 跨源校验 | 至少一个**独立出口 IP** 的源做同日同口径点值校验 |
| 判据先写死 | 阈值写在代码里，跑完不改 |
| 成品合规 | 最终 HTML 含首页三行免责；无评级 / 目标价 / 买入卖出 / 收益承诺类内容 |
| 退出码 | 0 = 无 blocking；1 = 有 blocking |

### 阶段 ⑤ 报告

```powershell
python scripts/build_report.py --exp <EXP>
```

| 验收项 | 判据 |
|---|---|
| 单文件 | 图片 base64 内嵌、CSS 内联、字体回退系统字体 |
| 离线可读 | 双击即开、断网可读、可直接打印 |
| 免责 | 首页三行：内部研究模拟 / 非持牌机构 / 不构成投资建议与收益承诺 |
| 「原文说的」与「实测的」分开 | 前者在引用栏，后者进 `metrics.json`，由审计分别校验 |

## 3. 新开一个实验的清单

1. 在 `experiments/registry.md` 顶部插入一行（模板在文件里）。
2. 复制 `templates/report_template.html` 改写，或先跑一次 `build_report.py` 确认模板可用。
3. 改 `scripts/fetch_market_data.py` 的窗口常量，用新的 `--exp` 取数（**不要污染既有快照**）。
4. 跑 5 步（见上）。
5. 参数、结果、结论状态（含失败与被证伪项）填回 `registry.md`。
6. **口径有新增或推翻 → 同步改 `data_contracts/` 三份契约**。契约才是复用的单位。

---

## 4. 回滚

| 场景 | 动作 | 影响面 |
|---|---|---|
| 某个实验的结论要撤回 | 把 `registry.md` 该行标记为「已撤回」并写明原因；`experiments/<EXP>/` 整个目录可删 | 只影响该实验行 |
| 某份契约写错了 | 改 `data_contracts/` 对应文件 + 在 `experiments/registry.md` 记录哪几个实验受该契约影响 | 需要连带复核受影响的实验 |
| 整个仓库要撤销 | 删仓库目录即可；不改动任何平台 project / issue | 无平台侧影响 |

> 仓库是**纯新增资产**：不修改任何已有 project / issue 的状态，不需要迁移既有数据。

## 5. 已知的流程缺口（写在前面，别当成不存在）

| 缺口 | 现状 | 影响 |
|---|---|---|
| **换手率无实测** | 只在 `metric_definitions.md` §5 写了口径定义 | 组合级结论暂时不能出 |
| **回撤口径可能非收盘** | 原文/媒体口径可能是日内最高→最低（见 `docs/second_article_trial.md` D2） | 主张与实测口径不一致时要报两套，不能只报一套 |
| **产品级数据无源** | 私募净值、规模、备案需付费或受限数据 | 相关主张一律记「不可复现」，不用代理冒充 |
| **审计独立性受单体约束** | 同一 agent 扮演建模与审计 | 靠代码路径隔离保证，不等于跨 agent 隔离 |
