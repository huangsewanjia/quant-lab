图 1 · quantdb 数据流。上游调用先经过限流、重试与调用日志；原始层按交易日分区写 Parquet，并为每个分区写行数与 sha256 manifest；DuckDB 只读查询由 ql 承担，质量闸独立复算。

L0 只追加；L1 用主键 upsert。分区 manifest 是断点与审计的共同依据：manifest、文件、字节数、sha256 四项都匹配才跳过。DuckDB 的溢写目录固定到 /srv/share/quantdb/staging/tmp，避免写满 SSD。

1.2 schema 与口径

db/schema.sql 覆盖 trade_cal、stock_basic、daily、adj_factor、daily_basic、stk_limit、suspend_d、index_daily、index_weight、income、balancesheet、cashflow、fina_indicator、dividend、namechange。主键、单位注释与 PIT 列都在 schema 内，不依赖外部约定。

4. 怎么回滚

代码

git revert <sha>，然后重跑 pytest db/tests -q 与 python -m db.checks.run all。

DuckDB

停止写入，备份 /srv/share/quantdb/db/quantdb.duckdb；删除后执行 init-db 与 load --full-refresh，从 raw 重建。raw 不被 ETL 删除。

raw 分区

按 manifest 的 sha256 定位异常分区，重拉该分区覆盖。manifest 与文件不一致时 ETL 不会跳过。

政策

删除 policy/<source>/<sha16>/ 与 index.json 对应条目，重跑采集；不影响行情库。
