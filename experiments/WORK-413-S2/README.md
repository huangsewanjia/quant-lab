## 两个脚本怎么跑（输出路径已参数化，可开箱即跑）

```powershell
cd experiments/WORK-413-S2

# 默认：结果写到仓库内 experiments/WORK-413-S2/rerun/（.gitignore 已排除，不覆盖已入库的实测证据）
python probe_armA_no_registry.py
python probe_armB_registry_guided.py

# 自定输出路径 / 只打印不写文件
python probe_armB_registry_guided.py --out D:\tmp\armB_rerun.json
python probe_armB_registry_guided.py --no-write
```

> 两个脚本里**已无任何仓库外的绝对路径**（原先写死的是本单工作目录），默认输出走仓库相对路径。
> **ARM B 可以复跑**：5 次请求全部落在已知可用源上（腾讯 ×2、新浪 ×1 + 2 次复验），测量值应逐字复现，只有 `elapsed_sec` 与 `provenance.run_at` 会变。
> **ARM A 不建议重跑**：它的失败数取决于跑批当时各源的可用性（东财限流、网易 502、腾讯日期格式坑），重跑**不构成同一次实验**。要跑请用 `--out` 另存，别覆盖入库证据。

## 关键实测结论

| 指标 | 前（ARM A） | 后（ARM B 补测/复验段） |
|---|---|---|
| 取数探测 HTTP 请求 | 6（其中 **4 次注定失败**） | **5（0 次已知失败源探测）** |
| 取数探测耗时 | 2.50 s | **1.18 s** |
| 口径裁定组合试算 | **42** | **7** |

**另有一条 ARM B 主跑批的记录（未入库）**：一次性脚本 `_armB.py`，**7 次请求 / 2.05 s**（B1 取数 4 次 1.56 s + B2 口径段 3 次 0.49 s）。它比入库的补测段多取中证500 与新浪 sh000510，墙钟因此更长。**两个数字对应两次不同的跑批，不可混用**；本目录的「后」一栏统一采用**入库可复跑**的补测/复验段。

### 三个常被混用的数字

| 数字 | 含义 | 证据强度 | 出处 |
|---|---|---|---|
| **6 → 5**（次请求） | **本轮 A/B 实测**：ARM A → ARM B 补测/复验段 | 实测 | `armA_result.json` / `armB_result.json` |
| **≈51 → 5**（次请求） | **跨任务参照**：前一个是 WORK-404 的**重建基线**（从其自身痕迹重建，非实测），后一个是本轮实测 | 重建 vs 实测 | `docs/second_article_trial.md` §5.2 |
| **42 → 7**（次组合试算） | **本轮 A/B 实测**：42 = ARM A 盲试网格行数，7 = ARM B 实际试算次数 | 实测 | `armB_result.json` → `blind_grid_rows` / `registry_path` |

## 本实验的已知缺口

- **S2 的判定表未过 `audit/audit_recompute.py` 独立复算**。该脚本的复算项是 WORK-404 口径（16 个数字写死在脚本里），不适用于本实验。已在 `experiments/registry.md` 显式标注，**不当作「已验收」**。审计契约见 `audit/README.md`。
- 证据强度：单篇、单会话、单网络条件，**样本量 = 1**。ARM A 是**路线复现不是盲测**，「前」是真实成本的**下界**。
