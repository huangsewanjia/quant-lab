## §2 因子装配阶段的三个实现缺陷（`scripts/work555_features.py`）

### §2.1 PIT 成员判定恒为真（**最严重**）

- **现象**：预注册 §2 要求「交易日 t 的成分 = 快照日 ≤ t 的最新月末快照」。首版实现把成分表 `members` 的 `con_code` 改名为 `ts_code` 后与事实层做 `how="left"` 合并，再用 `feat["ts_code"].notna() & feat["trade_date"].notna()()` 判成员。
- **根因**：pandas 的 left merge **不会把左表的键列置空**（实测：`left.merge(right, on=["k"], how="left")` 后左表键列保持原值，右表非键列才变 NaN）。而 `members` 改名后与事实层**只有键列相同**，右表侧根本没有可用来判定命中的非键列 → `is_member` 对**全部行**都为 True。
- **后果**：PIT 成分过滤完全失效，样本池从「沪深300 成分」退化为「曾进过沪深300 的全部个股并集」。
- **实测证据**：修复前 `[pit] member rows` 无输出；修复后 `member rows=1,095,303 | 每日成分数 min=295 med=300 max=300`。全库 820 只、逐日 300 的结构恢复。
- **修复**：合并时给右表加一个**非键标记列** `_m`，用 `rows["_m"].notna()` 判成员，合并后丢弃 `_m`。
- **性质**：实现缺陷，不是协议变更（PIT 规则未动）。

### §2.2 `get_indexer` 方向写反

- **现象**：断言 `样本行未能在归一化池中定位` 触发，报 `unmatched 183849 / 918721`。
- **根因**：`MultiIndex.get_indexer(target)` 返回的是**调用方索引中**目标键的位置。首版写成 `key_samp.get_indexer(key_pool)`，于是 `idx[i]` 是「第 i 个池行在样本中的位置」，而后续却按 `X = poolX[idx]` 当作「样本行在池中的位置」使用。
- **修复**：改为 `idx = key_pool.get_indexer(key_samp)`。
- **注意**：两个方向的 `len(idx)` 不同（池 918,721 vs 样本 734,872），**这个不对称正是最早的报警信号**，首版却误读成「样本行没对齐」。

### §2.3 回测事实层对训练段误用断言

- **现象**：断言 `测试段样本行未能在回测事实层中定位` 触发。
- **根因**：回测事实层只覆盖测试段（2017-01-01~2020-12-31），而样本含训练/验证段；`bt_row_id` 对训练段样本天然为 −1（不在回测层内），首版却用 `assert (bt_row_id >= 0).all()` 把「不在回测层内」当成错误。
- **修复**：训练/验证段允许 −1，另立断言「测试段样本行必须全部命中」+「训练/验证段样本行必须全部为 −1」。

### §2.4 停牌标记列缺失

- **现象**：`KeyError: 'is_suspended'`。
- **根因**：`suspend_d` 筛选后只保留了两列键列，合并后没有生成 `is_suspended`。
- **修复**：在合并源上显式加 `sus_s["is_suspended"] = True` 作为非键标记列（与 §2.1 同理）。

## §3 引擎梯度校验抓出的三个反向传播缺陷（`scripts/work555_dee.py`）

> 这些缺陷如果没被 `scripts/work555_test_primitives.py` 的有限差分梯度校验拦住，
> **模型会正常训练、正常出数、但学出来的东西是错的**——不会有任何报错。

### §3.1 BatchNorm 反向多除了 B

- **现象**：`grad_check[mlp]` 相对误差 `1.000e+00`，参数 `b1`，`gnum=0.000e+00 / g=-1.455e-09`。
- **根因**：`_bn_backward` 把标准形式 `dL/dz_j = (1/σ)[g_j − mean(g) − x̂_j·mean(g·x̂)]` 后面又乘了一个 `1/B`。
  其中 `B` 只应出现在 `mean()` 里一次。
- **修复**：删掉多余的 `/ B`。
- **附带**：BN 的 `b1` 梯度**解析上恒等于 0**（损失对 z 的常数平移不变），
  所以数值梯度也是 0；测试里把「两边都近似 0」判为一致，避免用相对误差除以 0 噪声。

### §3.2 软决策树链式法则缺 `g` 因子

- **现象**：`grad_check[tree]` 相对误差 `3.776e-02`，`gnum=1.524e-05 / g=1.643e-05`。
- **根因**：反传时用了 `dprob_parent += dL_child_left + dL_child_right`，
  但 `prob_left = par·g` ⇒ `∂prob_left/∂par = g`（不是 1）。正确的链式是
  `dprob_parent += dL_left·g + dL_right·(1−g)`。
- **修复**：改为 `dprob[:, ids] += dl * g + dr * (1.0 - g)`。

### §3.3 软决策树反传整段漏掉 `dy`

- **现象**：修完 §3.2 后仍 `max_rel=1.000e+00`；用「软门全路径枚举」的独立暴力实现对照，
  解析梯度比数值梯度**大约 1000 倍**，三个参数族（a / b / mu）**等比例**偏大。
- **根因**：`out_b = Σ_ℓ P(b,ℓ)·μ_ℓ`，故 `dL/dP(b,ℓ) = dy_b·μ_ℓ`；
  首版写成 `dprob[:, leaf_ids] = μ`（把 `dy_b` 漏了），`dμ_ℓ` 也漏了 `dy`。
- **修复**：`dprob[:, leaf_ids] = dy[:, None] * mu[None, :]`；`dmu = (prob[:, leaf_ids].T @ dy)`。
- **量级佐证**：漏掉 `dy` 相当于把损失当成「预测值本身」而非「预测减标签」，差一个量级因子，
  与观测到的 ~1000 倍偏差一致。

### §3.4 软树门控的独立暴力验证

除有限差分外，另用**全路径枚举**的暴力实现（逐样本沿所有根→叶路径枚举概率乘积）
对照 `forward` 与解析梯度：`forward max|diff| = 2.07e-08`；
梯度对照在 float64 下 `a` / `b` / `mu` 的最大相对误差分别为
`1.226e-03` / `9.359e-04` / `1.418e-05`（且误差项本身处于 1e-11 量级的近零梯度上）。

### §3.5 有限差分噪声与「可分辨性」判据

`grad_check` 初版用 float32 前向做有限差分：损失本身的舍入噪声约 `1e-9`，
在 `eps=1e-3` 下被放大成 `5e-7` 的梯度噪声，直接淹没真实信号，
导致 lasso / elasticnet / tree 出现「假失败」。
处置：① 有限差分前把参数与输入升到 **float64**；
② 用**两个步长**（`eps` 与 `eps/10`）的一致性判定该分量是否**可分辨**，
不可分辨的分量单独计数而不计入失败（不依赖解析值来自证）。

### §3.6 Lasso / elasticnet 的 L1 拐点

L1 次梯度在 `w=0` 处不连续，有限差分跨过拐点时测的是拐点不是梯度。
处置：梯度校验前把 `w` 推离 0（`N(0, 0.5)`），并跳过 `|w| < 1e-2` 的分量。

## §6 回测掩码与断言的三次返工（`scripts/work555_backtest.py`）

### §6.1 买入掩码没在选股阶段生效

- **现象**：断言在 `buy_fill` 处报 `reason=limit_up`。
- **根因**：`can_buy` 只用了 `has_trade & listed & member`，**没有把涨停排除在候选之外**；
  涨停股照样进了 top-50，然后在成交阶段被拦下 → 断言报的是「掩码没做」而不是「数据有异」。
- **修复**：掩码在**选股阶段**就排除涨停（以及停牌、缺 limit），断言只负责**复核成交时的可成交性**。

### §6.2 方向感知的可成交判定

- **现象**：断言在 `sell_fill` 处报 `reason=limit_up`。
- **根因**：可成交复核函数不分方向，把「涨停」当成了对卖出也成立。
- **修复**：复核函数加 `side` 参数——买入拦涨停、卖出拦跌停（`limit_missing` 是预注册的显式豁免，不触发断言）。

### §6.3 「卖不掉」是合法结果，不是违规

- **现象**：断言在 `sell_fill` 处报 `reason=limit_down`。
- **根因**：把「因跌停/停牌而强制持有」当成了违规读价。
- **修复**：断言只挂在**实际成交**的路径上（`sell_fill` / `buy_fill` / `settle`）；
  「不可卖 → 强制持有」走另一分支，不触发断言。
  另加 `settle` 断言：停牌股权重若发生变化 → 报「在不可成交价上做了交易」。

### §6.4 `--no-mask` 演示开关此前无效

- **现象**：`--no-mask` 跑完 `n_guard_violations = 0`，断言没被触发。
- **根因**：掩码开关与断言开关用了同一个字段（`guard.enforce`），
  关掩码等于同时关断言。
- **修复**：拆成 `guard.enforce`（断言，始终 True）与 `guard.mask_enabled`（掩码，可关）。
- **现状实测**：掩码开启 → `n_guard_violations = 0`；
  掩码关闭 → 立即抛
  `UntradablePriceRead: UNTRADABLE_PRICE_READ ts_code=000839.SZ trade_date=2017-02-17 reason=limit_up purpose=buy_fill`。

## §7 独立复算抓到的标签存储精度差

- **现象**：独立复算首轮报 `BLOCKING: ic::xgb_s42::test_rankic_mean 0.014751637781607357 != 0.014751702842600519`，
  相对差 `4.41e-06`（阈值 1e-6）。
- **根因**：建模侧的标签取自 `sample.npz`（**float32 存储**），审计侧取自事实层
  `data/WORK-555/panel_backtest.csv`（float64）。两者差在**存储精度**，不在算法。
- **处置（不是「放宽阈值」）**：审计脚本改为
  ① 用**与建模侧完全相同的标签数值**（`sample.npz` 的 float32）复算 IC —— 比的是算法不是存储精度；
  ② 另立一项**数据完整性检查**：`sample.npz` 的标签与事实层标签的偏差必须 ≤ 1e-6（float32 存储精度上限约 6e-8），
  超出即 blocking。复算与建模侧结论一致，标签完整性检查也通过。

## §8 数据侧诊断：为什么绝对水平低（不是泄漏，是协议与面板的适配问题）

这一节的每条都有可复跑的实测证据，不是推测。

### §8.1 无前视泄漏的三条证据

| 检查 | 方法 | 结果 |
|---|---|---|
| placebo | 把当日标签在截面内打乱后重算各因子 RankIC | 真实 median&#124;IC&#124;=0.057 → placebo 0.0017（placebo 的 95 分位 0.0048）→ 信号是真实的截面关系 |
| 过去收益探针 | 特征(t) 对**已实现**的过去收益(t−1→t) 的 IC | 量/波类 20 个因子 median&#124;IC&#124;=**0.012**（干净）；价/动量类 28 个因子 median&#124;IC&#124;=**0.318**（动量因子本来就是滞后收益，机械相关，非泄漏） |
| 构造审读 | 48 个算子逐条审读 | 全部为**后视窗口**（`rolling(w)` 尾随、`shift(+w)`、`shift(−1)` 只用于造标签）；无负向 shift、无居中窗口 |

### §8.2 信号是排序驱动的，MSE 看不见

测试段逐因子对比（Spearman = 看排序，Pearson = 看线性）：

| 因子 | Spearman | Pearson |
|---|---|---|
| ROC_5 | −0.0369 | −0.0055 |
| MA_DEV_10 | −0.0328 | +0.0008 |
| QTLU_5 | −0.0330 | −0.0022 |
| AMT_STD_20 | −0.0259 | −0.0180 |
| VOL_STD_20 | −0.0110 | +0.0120 |

单一因子层面 Spearman 比 Pearson 高 6~7 倍；
而 DEE 的三个模型族（含论文原版 XGBoost）**全部按 MSE 训练**，
MSE 只对线性部分敏感 → 模型能看到的信息远少于排序信息。

### §8.3 论文原版 XGBoost 在本面板上同样退化（冻结配置本身）

按预注册 §4.6 冻结的 XGBoost 配置（2000 棵、lr 0.05、深度 6、早停 patience 50 监控验证 MSE）实测：

| 轮数 | 验证 RMSE | 测试 RankIC | 验证 RankIC |
|---|---|---|---|
| 早停触发（第 0~1 轮） | 0.0318024（平） | +0.0148 | +0.0256 |
| 50 | 0.0318025 | +0.0242 | +0.0374 |
| 200 | 0.0318124 | +0.0222 | +0.0398 |
| 600 | 0.0319146 | +0.0241 | +0.0435 |

验证 MSE 从第 0 轮起就是平的 → 早停把模型停在第 0~1 轮 → 近乎常数预测器。
**这是「用池化 MSE 做早停」这个协议在本面板上的适配问题，不是本单实现问题**
（论文用的是 qlib 官方 Alpha158 面板 + 158 因子 + 无成本 + 10 种子，与本单不是同一个实验）。

### §8.4 复权口径核对（确认面板无污染）

- `close_hfq / close_raw` 的比值是**分段常数**（只在除权除息日跳变）；
- 例：000008.SZ 在 2013-05-28 原始价 14.40→7.16（2:1 拆股），后复权价 14.40→14.32（基本持平）→ **复权正确吸收了拆股**；
- 原始价日收益 |r|>3% 的行中 99.5% 的行后复权收益同样 |r|>3% → 其余是真实涨跌，不是复权伪跳变；

  因此 F27/F31~F37 等量价类因子在除权日附近有轻微污染。该口径沿用仓库既有规定，本单未改。

### §15.3 为什么不能靠「放宽阈值」消掉

预注册 §7 判据 2 写死了处置方式：

> **独立复算不一致**：审计脚本复算的 RankIC / IC / Sharpe / 年化 / MDD / 换手
> 与建模侧相对差 > 1e-6 → **以复算值为准**，回退到对应阶段重做。

放宽审计的 `TOL`、或把这一项降级，都等于把预注册冻结的判据改掉 —— 属于
§7 判据 6「协议变更」，预注册落盘后不可静默更改。
且判据 1「不可复现」的要求是「同一 commit + 同一快照 + 同一命令重跑」——
一个第三方拿不到 float64 内存值、只能从 float32 产物复算，这本身就是**可复现性缺陷**。

### §15.4 处置：让产物无损（float64 落盘），而不是动判据

**改什么**：`scripts/work555_dee.py` 与 `scripts/work555_xgb_diag.py` 的落盘语句
`pred=pred_te.astype(np.float32)` → `astype(np.float64)`；
`per_expert_pred` 与 `expert_valid_rankic` 同步改 float64（族消融复算同理）。
标签 `y` 保持 float32（内存中本就是 float32，无损失）。

**不改什么**：训练轨迹、指标计算、预注册判据、审计阈值（`TOL = 1e-6` 原样保留）——
**float64 落盘这一步不改变任何指标计算**，变的只是落盘精度。

> 口径限定（第四轮审查 N4-2 提醒后补记）：「建模侧数值未变」指的是**落盘精度这一步**
> 不改变指标计算；v2 → v4 之间 `dee_s43` 的 `test_rankic_mean` 确实变了
> （0.023148644058997664 → 0.02163083350961915），但那是 §13 的 S2 早停监控量修复
> 经**全量重跑**落到产物上的结果，与 float64 无关（见 §13 生成块逐行披露）。

**为什么必须重跑**：落盘精度写在建模脚本里，只有重跑才能得到新产物。
本轮（v4）覆盖 4 臂 × 2 种子（`scripts/work555_run_arms_v4.sh`），
