## 三、实现缺陷（自查发现并修复，均在出结论之前）

这一节是本单最要紧的部分：**下面每一条都会让三臂结论失真**，且都是我在自查阶段发现的，
不是外部评审发现的。列出实测证据与修法。

### 3.1 `ts_rank` 取错了「窗口最后一个元素」——**关键缺陷**

- **现象**：训练段样本数为 0、训练 loss = 0.000000、验证 RankIC = NaN。
  首版实现 `last = neg_inf[:, -1:, :]`，本意是取窗口里最后一个交易日的值。
- **根因**：官方 torch 用 `x.unfold(0, w, 1).permute(0, 2, 1)`，窗口轴在**第 1 位**；
  而 numpy 的 `sliding_window_view(x, w, axis=0)` 窗口轴在**末位**。
  在 numpy 布局下 `[:, -1:, :]` 取的是**最后一列股票**，不是最后一个交易日。
  该式子不报错、也不产生 NaN，只会把 rank 算成 0，再经 `neutralize_day` 的
  `sd <= 0` 把整行截面丢掉——训练段因此被清空。
- **修法**：把移植改成与官方**逐字直译**（窗口轴放回第 1 位），并新增
  `scripts/work449_test_primitives.py`：把官方 6 个原语转写为 torch 参考实现，
  与 numpy 移植逐格比对。
- **实测**：6 原语 × 3 窗口 × 6 组随机面板，**掩码 0 处不一致**；
  值最大相对差 1.1e-13（ts_rank 5.7e-8，源于官方把 rank 转成 float32）。

### 3.2 `ts_std` 分母多了一维广播

- **现象**：`ts_std` 抛 `could not broadcast input array from shape (128,128,7) into shape (128,7)`。
- **根因**：`n` 是 `(L, N)`，却又取了 `[:, None]`，把 `(L, N)` 除成了 `(L, N, N)`。
- **修法**：去掉多余维度，改成官方写法 `(n - 1)` 直接相除。

### 3.3 `no_mask` 掩码定义偏离协议 §5.2——**会让三臂塌缩**

- **现象**：首版 `m_no = has_row`（有源数据行才算格）。
  但 AKShare/东财在停牌日**不返回行**，于是停牌格被排除在 no_mask 之外，
  no_mask 与 halt_only 的差别退化成「只剩上市满 1 年与否」，**掩码实验本身失效**。
- **协议原文**（§5.2）：「no_mask：不施加任何掩码，因子与标签读取**全部**格子
  （停牌行价格按 `field_dictionary.md` §5 前向填充，**属数据事实而非掩码**）」。
- **修法**：面板改为**稠密网格**——股票从第一个源数据行到最后一个源数据行之间都有面板行，
  窗口内无源数据行 = 停牌（价格前向填充到上一收盘、成交量与成交额置零）；
  窗口外 = 未上市/已退市（无行）。
- **实测**：稠密面板格 1,620,295（源数据行 1,575,502、窗口内停牌 44,793、
  未上市/已退市 199,385）。功效检查重跑：测试窗 full_mask 掩码率
  **1.9077% ≥ 0.50% → 仍锁定 CSI300**，与修订前的结论一致。

### 3.4 预测落位错位一天

- **现象**：首版把模型输出落在 `t+1`，导致组合在 t 日用的是**一天前的信号**。
- **协议原文**（§9.2）：「逐日：算 `corr(ŷ_t, r_{t+1})`」；§8 组合「权重滞后一期使用」。
- **根因**：训练脚本里的验证 RankIC 用的是 `ŷ_t vs r_{t+1}`（正确），
  而推理落位写成了 `t+1`，两处口径自相矛盾。
- **修法**：统一为「`pred[t]` = 由 t 日因子做出的对 `r_{t+1}` 的预测」，
  组合在 t 用当日信号建仓；表观 IC 也改为 `corr(pred[t], r_{t+1])`。

### 3.5 `adj_close` 前向填充取到陈旧值

- **现象**：`last = np.where(np.isnan(last) & ~np.isnan(acc), acc, last)`
  只在**第一次**取到值后就不再更新，停牌日沿用**首个**收盘价而非最近收盘价。
- **修法**：改为 `last = np.where(np.isnan(r), last, acc)`（最近一次有效收盘）。

### 3.6 `range_1` 分子分母量纲不一致

- **现象**：`(high − low) / adj_close`，而 `adj_close` 是从 1.0 起累乘的**收益指数**，
  `high/low` 是 hfq **价格**——量纲不一致。
- **修法**：分母改为同源的 hfq 收盘价 `close_hfq`。

### 3.7 SLSQP 交叉校验的梯度被错误掩码

- **现象**：QP 与 SLSQP 的最大相对差 **7.74e-3**，远超 1e-6 的门槛。
- **根因**：`grad()` 返回 `g * (x > 0)`，把处于下界 0 且梯度为正的变量也置零，
  等于让 SLSQP 停在**另一个**最优点上，交叉校验比的根本不是同一个解。
- **修法**：去掉梯度掩码，把箱约束交给 scipy 的 `bounds` 处理。
- **实测（修后）**：最大相对差 **8.16e-14**，目标函数值一致到 1e-16。

### 3.8 QP 求解器慢到回测不可行

- **现象**：单日 QP 在 200 次水位二分的实现下约 6–7 s/天 → 726 天 × 3 臂 ≈ 4.8 小时，
  不可接受。
- **修法**（**不改变方法**：仍是「投影梯度 + 二分水位精确投影」）：
  二分步数从 200 降到 52（区间缩小 2^52 倍，远超双精度，投影仍精确）；
  增加上一日解的 warm start（只改迭代路径，不改最优解，目标函数严格凸）。
- **实测**：0.37 s/天 → 约 4.5 min/臂；warm start 与 cold start 解差 **0.000e+00**。

### 3.9 多线程 LAPACK / torch 在本机严重退化（训练与回测慢的真正原因）

- **现象**：把二分步数降下来之后，回测仍然要 20–25 min/臂。逐项计时发现
  **QP 只迭代 2 次**（早收敛），瓶颈根本不在 QP，而在协方差的特征分解。
- **实测**（600×600 对称特征分解）：

  | 线程数 | `eigh` | `eigvalsh` |
  |---|---|---|
  | 1 | **0.062 s** | **0.026 s** |
  | 2 | 0.054 s | 0.019 s |
  | 4 | 1.193 s | 0.239 s |
  | 8 | **5.379 s** | **3.853 s** |

  8 线程比单线程**慢 87 倍**——线程过度订阅 + 自旋等待。
- **同类问题在 torch 上更严重**（单步训练，batch 4096）：

  | torch 线程数 | 每步耗时 | 60 epoch 预计 |
  |---|---|---|
  | 1 | 9.79 ms | 2.0 min |
  | 3 | 7.69 ms | 1.6 min |
  | 8 | **163.30 ms** | **33.5 min** |

  注意：`OMP_NUM_THREADS` **对 torch 无效**（torch 用自己的线程池），
  必须显式 `torch.set_num_threads()`。第一版脚本没设，导致三臂训练跑了 30 分钟仍未过半。
- **修法**：
  - 回测与报告渲染统一 `OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1`；
  - 训练脚本显式 `torch.set_num_threads(2)`（三臂同设置，保证数值可比与可复现）。
  这是纯运行环境修正，**不改变任何数值结果**（特征分解是确定性算法，
  线程数只影响调度；但三臂必须同线程数，否则浮点求和顺序不同、不可比）。

### 3.10 Ledoit-Wolf 收缩公式用错，导致协方差退化成等比阵——**关键缺陷**

- **现象**：回测里 Ledoit-Wolf 的收缩强度 **δ 恒等于 1.0**，协方差永远是 `μ·I`
  （等比阵），组合等于完全忽略股票间相关性。
- **根因**：我写的是 Ledoit-Wolf **(2003)** 的 `b̄²/d̄²` 公式，
  而官方实现（`src/mlquant/portfolio/markowitz.py`）用的是
  **sklearn 的 `LedoitWolf`**，即 **(2004)** 的 `β/δ` 公式。两套公式不同，
  我的 `b2` 因为含 4 阶矩而恒大于 `d2`，被 `min()` 夹到 1 → δ=1。
- **对照实测**（修前）：

  | n | t | δ 我的实现 | δ sklearn | 协方差最大相对差 |
  |---|---|---|---|---|
  | 300 | 120 | 1.000000 | 0.030315 | 6.99e-01 |
  | 680 | 120 | 1.000000 | 0.035688 | 6.98e-01 |
  | 300 | 2000 | 1.000000 | 0.001792 | 6.27e-01 |

- **修法**：按 sklearn 源码逐项重写（`β = 1/(N·T)·(β_/T − δ_)`、
  `δ = (‖S‖²_F − 2μ·Σdiag + Nμ²)/N`、`shrinkage = min(β, δ)/δ`）。
- **实测（修后）**：7 组 (n, t) 全部 `max_rel_diff ≤ 3.4e-16`，
  δ 与 sklearn 逐位一致。新增 `scripts/work449_test_covariance.py` 固化该对照。
- **影响范围**：修前跑出的 `metrics_full_mask.json` 全部作废（三臂均需重跑）。

### 3.11 求解器交叉校验的「相对差」口径（**最终轮次实测：两个口径都超阈**）

- **现象（初版，作废轮次）**：QP 与 SLSQP 的**权重**最大相对差 1.75e-4，超过 1e-6 的门槛。
- **定位（初版）**：逐日拆解后确认两者**目标函数值相对差仅 6.5e-9**，即同一个最优点；
  权重差异来自目标函数在平坦子空间上的平移——当 `Σ = μI`（§3.10 的 bug 导致）
  且 `α=10` 时，目标函数的曲率 `H = 2αΣ ≈ 8.4e-3`，SLSQP 的 `ftol=1e-12`
  对应的位移恰好是 `√(2·ftol/H) ≈ 1.5e-5`，与实测的 ~1e-5 位移同阶。
  **权重级相对差在本问题下无法压到 1e-6 以下**，无论 ftol 调到多小。
- **⚠ 上面的 1.75e-4 / 6.5e-9 是 §3.10 修好之前的轮次与合成问题上的数字，不是交付轮次。**
  交付轮次（§3.10 修好、协方差有真实结构）的实测比它**大 27 倍 / 195 倍**，见下。
- **交付轮次实测**（`experiments/WORK-449/metrics_<arm>.json` 的 `solver_cross_check`，
  5 个抽样日 × 3 臂 = 15 个实例）：

  | 臂 | 权重口径 `max_rel_diff` | 权重口径超阈 | 目标函数口径 `obj_rel_diff` | 目标函数口径超阈 |
  |---|---|---|---|---|
  | `no_mask` | **2.8637e-03** | 5/5 | **1.2721851344898035e-06** | **1/5**（2023-12-18） |
  | `halt_only` | **4.686871e-03** | 5/5 | 5.3662e-07 | 0/5 |
  | `full_mask` | **2.8297e-03** | 5/5 | 3.2932e-08 | 0/5 |

  即：**权重口径 15/15 超阈**（最大 = 阈值的 2,830~4,687 倍）；
  **作者自己选的目标函数口径也有 1/15 超阈**（1.2722e-06 > 1e-6）。
  初版「以目标函数口径判读、门槛即通过」的写法**在本轮不成立**。
- **处置（已升级为协议修订 v1.4 §1）**：
  1. 预注册 v1.4 把「相对差 ≤1e-6」的**分母写死**为两个口径
     （A 权重口径 = `max|w_qp − w_slsqp| / max|w_slsqp|`；
     B 目标函数口径 = `|f_qp − f_slsqp| / |f_slsqp|`），
     并规定**合取判定**：A 与 B 都 ≤1e-6 才算一致；任一超阈即标「未通过 / 有条件」。
  2. 报告的门槛行改为如实写「**未通过 / 有条件**」，两个口径的实测值一律用
     **科学计数法**列出，不再四舍五入成「0.005 / 0.000」。
  3. 新增**材料性探针**（`scripts/work449_solver_materiality.py`），
     把「这个缺陷会不会翻掉判词」单独量化，见下条。
- **材料性探针的实测**（`experiments/WORK-449/solver_materiality.json`）：

### 3.13 预注册 v1.0 的优化器超参是**转录错误**，不是研究设计（关键缺陷）

- **核对**：抓取论文全文 `https://arxiv.org/html/2507.07107v2`（约 6.0 万字符），

  > "AdamW, lr 5e-4, weight decay 1e-5, gradient clipping 1.0, batch size 8192,
  > up to 60 epochs, early stopping on 10% validation holdout."

  官方实现 `initial-d/ml-quant-trading` 的 `configs/paper.yaml`（"Full paper-reproduction
  config"）与 `src/mlquant/training/trainer.py`（`AdamW` + `grad_clip=1.0`）**逐项一致**。

- **代价（实测）**：v1.0 超参下 `no_mask` 单臂墙钟 **29 分钟**；改成论文口径后

  此处只登记两个口径的实测值，不断言因果。
- **修法**：开 **协议修订 v1.3**，把优化器/学习率/权重衰减/梯度裁剪/batch 改回论文值；

- **架构没有错**：论文 §3.5.3 写「Two hidden layers (128 units, GELU, dropout 0.1) …

### 3.16 `work449_primary_test.py` 两个缺陷（一个崩溃、一个口径不一致——关键）

- **缺陷 (a) 崩溃**：`stats[i] = sharpe(a[sel], days) - sharpe(b[sel])` —— 第二项
  **漏传 `days` 参数**，`TypeError: sharpe() missing 1 required positional
  argument: 'days'`，主检验脚本**根本无法跑完**。
- **缺陷 (b) 口径不一致（更要命，且不报错）**：
  - 回测 `scripts/work449_backtest.py::metrics` 的年化分母是**自然日跨度**
    `np.datetime64(end) - np.datetime64(start)` = **1092 天**，
    `ann = (1+total)^(365.25/1092) - 1`；波动用 `std(ddof=1)*sqrt(252)`。
  - 主检验却把 `metrics["test_days"]`（**726 个交易日**）当分母，
    `ann = (1+total)^(365.25/726) - 1`。
  - 后果：主检验算出来的 ΔSharpe **不等于** 三臂各自上报的
    `Sharpe(no_mask) - Sharpe(full_mask)`，主检验量与报告量对不上，
    且年化收益被系统性高估约 1.5 倍。
- **修法**：主检验改为**从 `start`/`end` 复算自然日跨度**（新增
  `calendar_days()`），bootstrap 重采样按 `len(sel)/n_trading` **等比缩放**
  自然日跨度，使年化口径与回测一致。
- **验收**：修复后 `delta_sharpe_consistency_abs_err = 0.0`（主检验算出的
  ΔSharpe 与三臂上报 Sharpe 之差**逐位相等**），该字段已写入
  `primary_test.json` 作为常驻勾稽证据。

### 3.17 `audit/recompute_work449.py` 抽样索引缺陷（审计脚本自身崩溃）

- **现象**：抽样时把**扁平格号**直接当作行号使用
  （`pi = np.array([int(k) for k in idx])`，`idx` 取值到 `t*n`），
  索引 `rb.ret[i, j]` 越界 → `IndexError: index 77565 is out of bounds for
  axis 0 with size 2676`，**独立复算脚本跑不完**。
- **修法**：按 `pi = idx // n`、`pj = idx % n` 正确分解为 (行, 列)。
- **意义**：审计脚本自身带 bug 时，"审计通过"这句话没有意义——
  审计脚本必须先能跑通、再看它的结论。

### 3.19 seed 随机性未被主检验的 CI 覆盖（自发现的稳健性缺口，已量化）

- **现象**：AdjMSE 的权重由 `sign(pred)·sign(target) > 0` 决定，预测值恰好在 0 附近时
  **符号不连续**，于是线程数、浮点归约顺序等极小扰动会被放大成不同的训练轨迹。
  实测 seed 42 ↔ 43 的**测试段 IC**跨度：`mlp+adj` +0.0092 ↔ +0.0240、
  `linear+adj` −0.0043 ↔ −0.0443。
- **后果**：主检验的 bootstrap 95% CI 只覆盖**收益序列的抽样噪声**，
  **不覆盖模型/seed 随机性** ⇒ ΔSharpe 的**量级**（+0.55）不能当精确效应量，
  **符号是否稳健必须靠换 seed 复跑三臂来验**。
- **处置**：新增**换种子轮次**（seed 43，产物 tag `_s43`）与
  **同种子重跑轮次**（seed 42，产物 tag `_r2`）。前者测**种子敏感性**，
  后者测**可复现性**（协议门槛第 6 条第二判据）——**两者不能互相顶替**，
  报告里分列 §11.3 与 §11.4。
- **口径边界**：这两个轮次都是 **v1.4 落盘后**才入库，v1.4 的 commit 早于它们入库的 commit；
  它们**不改变**主交付轮次（seed 42）的任何数值，**不用于**改写主判词。

- 两轮的 ΔSharpe **量级几乎相同（0.5516 vs 0.5515）而符号相反**，
  且**两轮的 95% CI 都不含 0** —— 按预注册 §9.4 的机械规则，
  **同一套协议、同一份数据、同一批因子，仅换训练随机种子，判词就翻转**。
- 5 bps 敏感性口径下两轮 CI 都**含 0**（seed 42：[−0.0704, +0.8976]；
  seed 43：[−0.9383, +0.0126]），两轮都判「未复现」。
- **能站住的结论只有两条**：
  ① 协议冻结轮次（seed 42）的判词是「**未复现（退）**」；
  ② **表观 IC 轴的方向在两个 seed 下同为负**（−0.004418 / −0.002063），
  即「去掉掩码并没有让表观 IC 上升」这一条**对种子稳健**；
  **可实现 Sharpe 轴则不能下结论**（符号不由数据决定，而由训练随机种子决定）。
- **根因**（与 §3.18 同源）：AdjMSE 的权重由 `sign(pred)·sign(target) > 0` 决定，
  预测值在 0 附近**符号不连续**，线程数与浮点归约顺序的微小扰动会被放大成不同的训练轨迹；
  本单的模型预测截面离散度只有标签的 0.58%，落在符号翻转的敏感区。
  三个臂的换手因此剧烈变化（no_mask 双边换手 186.05 → 325.49；
  full_mask 407.86 → 110.15），Sharpe 随之翻面。
- **处置**：报告首页判词框内加了「稳健性警告」段、摘要加了同号条款、
  §11.3 与表 10 给出逐项对照、表 11 给出同 seed 重跑的逐项比对；
  registry 与本节同步披露。**未**因此改判词、**未**重跑更多种子来「凑」一个方向。
