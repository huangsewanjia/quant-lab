## 0. 为什么有 v1.1

v1.0 §10 写死了「读出用 MLP / 线性；`mlp_std` 分支按训练集统计量标准化」。
实现落地后实测发现：**训练集标准化在重尾坐标上产生极端离群 z 值**，
使 R0–R3 四个「匹配 MLP」对照臂的读出初始损失达到 8.5e3 ~ 9.2e3（SmoothL1），
其余四臂为 0.33 ~ 0.36，量级差 4 个数量级。原因见 §1。

改动只有一处：**`mlp_std` 分支标准化后裁剪 `[−8, 8]`**。
裁剪常数与本单 S1 标准化（v1.0 §10.1「裁剪 [−8, 8]」）完全一致，不是新引入的自由度。

## 1. 实测证据（改动前）

冒烟测试（`--rep-date-cap 20`，20 个预测日、19,202 样本）读出验证 SmoothL1：

| 臂 | 读出类型 | 是否用训练集标准化 | 改动前验证 SmoothL1 |
|---|---|---|---|
| `s1_only` | 线性 | 否 | 0.352586 |
| `s3_only` | 线性 | 否 | 0.341906 |
| `s1_s2` | 线性 | 否 | 0.330343 |
| `full` | MLP **带 LayerNorm** | 否 | 0.354914 |
| `r0` | MLP 无 LayerNorm | **是** | **8514.525391** |
| `r1` | MLP 无 LayerNorm | **是** | **9208.298828** |
| `r2` | MLP 无 LayerNorm | **是** | **3608.443359** |
| `r3` | MLP 无 LayerNorm | **是** | **3594.983887** |

诊断（`data/WORK-566/u_seed42_train.npy`，19,202 × 248）：

- 训练集标准差最小的 12 列全部落在 `P[8..15]`（= `σ^res`）。`σ^res` 是**块级**统计量
  （每块 8 个标量广播到该块全部样本），跨样本近乎常数 → 标准差 1e-6 ~ 2e-5。
  这类列标准化后 |z| ≈ 1（本身无害）。
- 真正的放大源是重尾列：全 248 列标准化后 **max|z| = 20.36**。
  `mlp_std` 没有 LayerNorm 兜底（`full` 有），该离群值直接进入第一层线性 →
  预测值量级 ~1e2 → SmoothL1 损失 ~1e4。

另附：`σ^res` 这类近常数列在训练集标准差 < 1e-8 时按 sklearn `StandardScaler`
惯例**不再缩放**（scale 置 1），避免除以极小数。

## 2. 改动内容（唯一一条）

`scripts/work566_train.py::train_readout`：

```
xb = (xb - mu_u) / sd_u
xb = xb.clamp(-8.0, 8.0)      # ← 新增，仅 standardize=True（即 mlp_std）分支
```

`standardize=False` 的分支（`s1_only` / `s3_only` / `s1_s2` 线性读出、`full` 带 LayerNorm
的 MLP 读出）**代码路径完全不变**。

## 4. 与论文的关系

论文附录 I 原文：「Inputs are standardized using training-set statistics, with unused
coordinates set to zero and no concatenated LayerNorm.」
本单：
- 「unused coordinates set to zero」→ 实现上等价于**只取被用到的列**（被用列先标准化，
  未用列置零与不取是同一件事）✓ 一致；
- 「standardized using training-set statistics」✓ 一致；
- 额外加了 `[−8,8]` 裁剪 → **本单偏离**，列在这里，量级常数与本单 S1 口径一致。

由于论文未披露其离群值处理方式，本单无法声称与论文在该臂上完全可比；
R0–R3 的数字在报告里按「降级配置 + 数值保护」标注。

## 6. 同时记录的实现级提速（不改口径，只改速度）

为在共享 CPU 机器上把全链跑完，做了两处**数学等价**的提速，均不改变任何数值口径：

1. **S2 编码器前向**：`nn.TransformerEncoderLayer(norm_first=True)` → 等价的
   `F.scaled_dot_product_attention` 实现，权重沿用官方模块（初始化逐位一致）。
   自检证据见 `experiments/WORK-566/fast_encoder_selftest.json`：
   同一权重下 eval 模式逐元素最大差 **4.77e-07**（float32 舍入量级）。
   注：训练模式下 dropout 的**随机数消费顺序**与官方实现不同（两者同为合法 dropout）；
   种子已固定并记录，复现性不受影响。
   本机（i3-12100F，无 AMX）实测提速 3~11×；bf16 实测更慢，故仍用 fp32。
2. **读出预测合并遍历**：8 个臂原先各读一遍 `u`（本机 u 合计约 4.9GB，memmap 读取是瓶颈），
   改为每个切分只读一遍、一次写全部 8 个臂的预测 → 读取量降为 1/8。
   数值完全一致（同模型、同输入、同算式）。

以上两项均**不改变任何输出数值**（第 1 项在 eval 模式下逐元素等价；训练模式的差异仅来自
dropout 随机流，且已在 §6.1 的自检证据中标注）。
