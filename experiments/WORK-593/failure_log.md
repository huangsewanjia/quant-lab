## 2. 口径变更（全部在跑数前落盘，带归因测量）

### D1 · C1/V2 容差 1e-9 → 按字段分辨率推导（预注册 v1.1）

| 项 | 内容 |
|---|---|
| 现象 | v1.0 的 1e-9 相对容差下，C1（`vwap ∈ [low, high]`）违规 **7,094 / 6,156,584** 行（1.152e-3），超 1.0e-3 阈值 → 按 v1.0 §8 应「停」 |
| 归因测量（只测量，未算 IC） | 越界量分位 p50 = 1.06e-8、p90 = 1.59e-7、p99 = 2.00e-6、max = 4.49e-5；其中 6,405 行落在 `0.5/amount_yuan` 舍入上界内，其余 689 行为涨跌停锁死日（`low == high == close`）的除法噪声（例：`low=high=4.681053`，`vwap=4.681052`） |
| 处置 | 容差改为 `1e-6 + 0.5/(amount×1000) + 0.5/(vol×100)`，逐行；实测违规 **0** 行 |
| 是否放宽判据 | 否。阈值仍是「违规率 ≤ 1.0e-3」，只把容差按字段分辨率推导；1e-9 是起草时未按分辨率推导的错误 |
| 对结论影响 | 无（只因 C1 是数据层闸门；主检验量与其阈值未动） |

### D2 · V3（双路径逐值）按字面判「不通过」

预注册 §3 的 V3 判据写的是「最大绝对差 = 0」。实测 `a*10/vol` 与 `a*10*vol⁻¹`
最大绝对差 **4.55e-13**（相对量级 1e-16，IEEE-754 下两种写法不严格相等）。
**按字面判不通过**，不做事后改判据、不写「通过」。

## 4. 弃用与无效尝试

| 尝试 | 结果 | 处置 |
|---|---|---|
| `git fetch origin` 校验远端最新提交 | 两次均在 90~120 s 超时（`GnuTLS recv error (-110): The TLS connection was non-properly terminated.`） | 用缓存副本（HEAD `78e5b5e`，与缓存主线一致），在交付评论中写明「未与远端 diff，因为 fetch 失败两次」 |
