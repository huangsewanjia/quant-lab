## 只改一条：C1 / V2 的容差由 1e-9 改为「按字段分辨率推导」

**原文字（v1.0 §2 C1）**：容差 `1e-9 * |bound|`；C1 违规率 ≤ 1.0e-3。

**实测（v1.0 口径，跑数前）**：`data/WORK-593/panel_{E,C,P}.parquet` 三套表示各
6,156,584 股票-日中，违规 **7,094** 行，违规率 **1.152e-3**，**超过 1.0e-3 的阈值**。
按 v1.0 §8 该情形应「停」。停之前先做了归因测量（只测量，不算 IC）：

| 归因分量 | 行数 | 实测 |
|---|---|---|
| 全部违规 | 7,094 | 相对越界量的分位：p50 = 1.06e-8，p90 = 1.59e-7，p99 = 2.00e-6，max = 4.49e-5 |
| 其中：落在「`amount` 以 1 元为分辨率」的舍入上界内 | 6,405 | 上界 = `0.5 / amount_yuan` |
| 其中：单一行情（`low == high == close`，涨跌停锁死）日的浮点除法噪声 | 689 | 越界量 ≤ 1e-6 相对，例：`low=high=4.681053`，`vwap=4.681052` |

**结论**：1e-9 不是这两个字段能分辨的精度——`amount` 存的是**千元**（1 元分辨率）、
`vol` 存的是**手**（100 股分辨率），`vwap` 由两者相除得到，其相对误差下界本来就高于 1e-9。
1e-9 是 v1.0 起草时未按字段分辨率推导的错误容差，不是数据缺陷。

**改为（v1.1 生效，逐行容差，全部跑数前定死）**：

```
tol_rel(i) = 1e-6 + 0.5 / (amount_i × 1000)  +  0.5 / (vol_i × 100)
判据： low_i − tol_rel(i)·|low_i|  ≤  vwap_i  ≤  high_i + tol_rel(i)·|high_i|
```

- `1e-6`：浮点除法与归一化的数值噪声上界（本条覆盖 689 行锁死日噪声）；
- `0.5/(amount × 1000)`：`amount` 以千元存储、四舍五入到 1 元的半个末位；
- `0.5/(vol × 100)`：`vol` 以手存储、四舍五入到 1 手（100 股）的半个末位。

**新口径实测（跑数前）**：违规 **0** 行（6,156,584 行全过）。

**不改变的东西**：C1 的判据形态（区间包含）、C1 的阈值（违规率 ≤ 1.0e-3）、C2/C3/C4、
因子池 36 条、窗口、种子、主检验量与判定阈值。**v1.0 的 1e-9 口径的实测值（7,094 行 /
1.152e-3）照样写进报告**，与 v1.1 并列披露，不隐藏。

**V2 同步**：v1.0 §3 的 V2（区间命中率 ≥ 99.9%）用同一 `tol_rel`。v1.0 口径下的命中率
`0.998848`（6,149,490 / 6,156,584）也照样并列披露。
