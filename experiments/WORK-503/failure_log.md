## 5. 未取到 / 已知限制（不补全、不代理冒充）

- **历史 ST 标记**：接口不提供逐日 ST 状态，涨跌停只能用「板块限 ∪ ST 5%」的保守并集 → 非 ST 股当日恰好 ±5% 会被误掩码（只会削弱收益，不会虚增）。
- **JKP 13 因子**：无 A 股个股级对应值，先验改为自建 6 个 A 股因子（偏离 D2）→ `no_prior` 档的降幅大概率小于论文的 −15.2%，**该项不能用来支持「码本有效」**。
- **训练段长度**：本机无 GPU，训练段 2015–2019（论文 2009–2019）、≤6 轮（论文 ≤50）→ 绝对指标系统性低于论文。
- **上游 yaml 与论文正文的标签冲突**：正文 `open(t+1)→close(t+k)` vs yaml `close→close`，两份都写入预注册 D3，本单以正文为准。
- **`$vwap` 缺失**：Qlib 官方 cn_data 无该字段，Alpha158 的 price 组需要 → 用 `amount/volume × factor` 自算写入快照（偏离 D7）。
- **上游 stage-1 固定用 seed 42**：上游 `stage1.py` 写死 `fixed_seed = 42`，本单改为**每个种子各训一份 stage-1** 并在该种子的三档间共享（预注册 §13），偏离已在报告中披露。

### 7.2 我自己的错误（被边界单测当场抓出，已更正）

**v1.3 §4 的论证是错的**：我写「进带互为相反数 ⇒ 两种口径判词逐点相同 ⇒ 本修订不可能翻转任何判词」。
实际 `[−0.40, −0.15]` 取负是 `[+0.15, +0.40]`，**两者不相等**；只有退带 `[−0.10, +0.10]` 对称。
落盘后立刻补的边界单测 T2 在 121 个网格点上只有 71 个点成立，**当场判红**（正式训练当时尚未跑完，无任何正式结果可见）。

更正（预注册 **v1.4**）：读法 **A**（`Δ_drop` + 原带）与读法 **B**（`Δ_formula` + 进带取反）**逐点等价**；
字面读法 **C**（`Δ_formula` + 原带）与 A 的分歧被钉死在 `|Δ_formula| ∈ [15%, 40%]`，
且 C 会让「复现成立」在协议层面**不可达**（码本有效时 Δ_formula > 0，永远落不进进带）。
单测 T2 现在固化：121/121 点 A≡B、分歧区间精确、[−10%,+10%] 区间三种读法一致。

## 9. 终稿跑数阶段发现的两件事（都在正式结果产生后定位，均已改代码 + 写进报告）

### 9.1 「市值加权基准」的口径缺陷（已修 + 双口径并列披露）

| 项 | 内容 |
|---|---|
| 现象 | 自建的「PIT 名单 × 总市值」篮子在测试段累计 **+9.46%**，而同一份快照里的 **CSI300 指数是 −19.99%**；两者日收益相关性 0.98，累计差 30pp |
| 归因 | CSI300 是**自由流通市值**加权；本单拿不到 PIT 指数权重（探针 E4 只返回 1 只股票 1 个日期），也拿不到流通市值字段（财务快照只有 `bvps`），于是退化成**总市值**权重 → 权重全压在大行大油（601857 中石油、601288 农行、601398 工行、601988 中行、601088 神华），而这几只恰好是 2022–2024 的赢家（逐股贡献归因已核对） |
| 修法 | **主口径改用真实 CSI300 指数**（`data/WORK-503/index_sh000300.csv`，与 Tushare 探针逐字段一致：2024-01-10 close 3277.129 / open 3281.6692，差 0.0）；自建总市值篮子**保留为并列口径**并标注权重定义 |
| 是否动了阈值 | **没有**。预注册的阈值、判词带、组合规则一律未动；变的只是「基准是谁」这一实现口径，且两套口径的数字都报出来 |
| 阈值依据 | 预注册 §「基准调整 alpha」本来就要求「以 PIT 成分名单的权重（若不可得则用流通市值加权，权重口径写进报告）」——本单实现成了总市值，是实现偏离，不是协议变更 |

### 9.2 零成本诊断：净 SR 为负主要是换手成本吃掉的（**预注册外诊断，已标注**）

| 口径 | 种子 42 | 种子 2024 | 说明 |
|---|---|---|---|
| 净口径（主口径，买 5bps / 卖 15bps） | SR −0.542，AR −8.71%，对指数超额年化 −1.70% | SR −0.325，AR −5.53%，对指数超额年化 +1.84% | 预注册主口径 |
| 毛口径（诊断，买卖 0bps） | SR −0.042，AR −0.70%，对指数超额年化 **+6.70%** | SR +0.156，AR +2.76%，对指数超额年化 **+10.25%** | **预注册外**的诊断跑，只为拆解成本占比 |

- 日均单边换手 0.1667（即 TopK-DropN 每交易日换掉 5/30 只），成本拖累 ≈ 0.1667×(5+15)bps ≈ **3.3bps/日 ≈ 8.4%/年**；
- 结论：**信号本身有正的超额收益（毛口径 +6.7%~+10.3%/年），但在预注册的「只做多 + 日频调仓 + 5/15bps」组合口径下被成本吃光**，净 SR 转负。
- 这一条不改变任何阈值或判词规则，只是把「净 SR < 0 → 直接判退」这条硬规则**命中时的原因**写清楚，避免被误读成「信号无效」。
- 产物：`experiments/WORK-503/backtest_gross_diagnostic.json`（明确标注为预注册外诊断）。

### 10.3 这算不算「事后改口径」

**不算**：预注册 v1.1 只点名了基线**类**（`qlib.contrib.model.pytorch_gru_ts.GRU`）与「同特征、同 PIT 名单、同切分、同种子、同逐日 batch、同 MSE 损失」的协议，
**没有冻结基线的层数/隐藏维/优化器细节**；本单脚本里一直写的是 `hidden_size 64 / 1 层 / dropout 0.1 / AdamW lr 1e-3 / 余弦退火`，
只是这些值此前**没有真正传给 qlib**。修的是**传参 plumbing**，不是研究口径。
修完后的基线结构（已实测）：`GRUModel`，1 层、hidden 64、**43,073 个参数**，输出 (B,)。

### 10.4 一并加的一个小改动：回测输出标签

`scripts/work503_backtest.py` 新增 `--preds-tag`（默认空串 = 原行为不变）。
用途：三档成本（主口径 5/15 bps、单边 8 bps、双边 30 bps）与零成本诊断**并行跑**时，
各自的 `daily / rankic / trades / bench` 落盘互不覆盖。
**判定与审计读的那一套永远是 `--preds-tag` 为空的主口径文件**（`backtest_results.json` 与 `preds/<arm>_s<seed>_daily.parquet`）。

### 10.5 仍然成立的口径披露

- GRU 基线的 valid loss 在两个种子上都是**单调上升**（1.0033 → 1.0401 / 1.0133 → 1.0325），
  早停取最优 epoch（第 0 个）；这说明该基线在预注册的逐日 batch 协议下**很快过拟合**。
  这是**结果本身**，不是 bug；但也意味着「GRU 很强」这件事在本单口径下不成立。
- H2 的增量显著性因此必须按实测读，**不能**写成「基线弱、所以我们赢」。
