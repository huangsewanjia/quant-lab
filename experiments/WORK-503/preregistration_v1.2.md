## 1. 为什么这些修订不是「结果驱动的改协议」

1. 触发方式是**训练前的数据完整性审计**（对齐探针），不是看了回测数字之后回头改条件。
2. 修订发生时，仓库内**不存在**任何 checkpoint、预测文件或回测指标；四档消融与基线一次都没跑过。
3. 修订范围限于「把冻结条款正确实现出来」：
   - A、B 是实现与存储语义冲突（特征取错了日期）；
   - C 是把已冻结的契约条款落到代码；
   - D 是把「宁可多掩码」的原则落到复牌日；
   - E 是文字。
4. 判定阈值、样本期、种子、股票池、成本、组合规则**逐字未动**，因此修订不可能被用来「把失败调成通过」。

## 2. 修订后的数据完整性断言（进入报告与独立复算）

修订后必须逐条通过，任一条不过则不得开始训练：

| # | 断言 | 判据 |
|---|---|---|
| I1 | 二进制日历对齐 | 随机抽 20 只股票，用 `D.features` 取 `$close`，与新浪原始 CSV 的 `close_hfq` 逐日比对：**每个有行情的日子相对误差 < 1e-6** |
| I2 | 无空洞错位 | 上述比对中，任一有行情日的价格**不得**等于相邻有行情日的价格（除非该股连续两日价格恰好相同） |
| I3 | 全局日历一致 | `data/WORK-503/ds/calendar.txt` 与 `qlib_cn/calendars/day.txt` 逐行相同；样本数组按该日历定位 |
| I4 | 新股规则生效 | 样本索引中不存在「距首个有行情日 < 19 个日历日」的样本 |
| I5 | 掩码覆盖 | 测试期 PIT 样本：可交易率 ≥ 85%，否则命中失败判据 1（判「数据不可用」） |
