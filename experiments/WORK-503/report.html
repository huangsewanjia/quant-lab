1这单在问什么

PRISM-VQ 的核心主张是：把因子序列先用向量量化（vector quantization，VQ）压成一组离散「码本」， 再让预测器在离散隐空间上做横截面预测，比直接用连续隐空间更准。所谓「码本」就是一张查表：连续的隐向量被映射到有限个码字上， 离得最近的码字代表它。

要证伪这件事，最干净的办法是只拿掉码本这一件东西，其余（先验因子、MoE 混合专家、特征、切分、组合规则）全部保持不变， 看信号是否塌掉。本单因此跑了四档消融：

  • full：完整 PRISM-VQ（码本 + MoE + 先验）；
  • no_vq：去码本——不经过 VQ-VAE，直接用连续隐空间做预测；
  • no_moe：去混合专家（MoE）；
  • no_prior：去先验因子（6 个自建 A 股先验置零）。

判词规则（跑之前就冻结在预注册里）

主检验量 Δ_drop = (RankIC_no_vq − RankIC_full) / RankIC_full（预注册 v1.3 冻结的口径），取各档 ≥2 个种子的中位数： Δ_drop 落在 [−40%, −15%] → 判「进」（码本有效性复现成立）； 落在 [−10%, +10%] → 判「退」（未复现）；其余 → 判「部分复现」，必须写清偏差来源与翻案条件。

派单卡给出的字面式是 Δ_formula = (RankIC_full − RankIC_no_vq) / RankIC_full， 它与 Δ_drop 互为相反数：读法 A（Δ_drop 配原带）与读法 B（Δ_formula 配取反后的进带）逐点等价， 唯一不自洽的是字面读法 C（Δ_formula 配原带）——那会让论文自己的 −26.9% 判成「部分复现」，等于让「复现成立」不可达。 预注册 v1.4 把这一点写成了正确论证；两个带上的数字一次都没改过。 边界单测 scripts/work503_test_verdict.py 固化了两种自洽读法的等价性。

RankIC = 当日预测分数与实现收益的秩相关（Spearman），测试期日均；预注册 v1.0 / v1.1 / v1.2 / v1.3 / v1.4 与掩码契约 都在本单仓库内按时间顺序 commit，且早于任何正式回测产物。

审计里揪出的一个真问题（不是小修小补）

第一版落 Qlib 二进制时，把个股「有行情的日子」紧凑排列写入。但 Qlib 的 .day.bin 格式是按日历稠密的： 第 j 个数对应日历第 start_index+j 日。停牌造成的空洞因此会把该股之后的所有价格整体前移。 实测 724 只股票里 608 只存在空洞、合计 54,600 个日历日；探针显示某只股票 2012-01-06 的价格其实是 2012-01-09 的值。

这属于「取到的根本不是那一天的数据」的阻断性缺陷。修法（写成预注册 v1.2 §A）是在二进制层面改成日历对齐稠密写入， 停牌日按掩码契约前向填充到上一收盘、成交量与成交额置 0；修复后 I1 的 55386 个逐日比对最大相对误差 5.718918370282823e-08。

此外还做了两项检查：前视偏差抽查（lookahead_check.json）把特征轴、先验轴、标签轴分别与原始数据对拆， 特征 2742825 个值、先验 1971865 个值最大绝对偏差都在 1e-6 量级、0 处日期错配； 掩码断言在回测引擎里是活的（涨停不可买、停牌不可交易、成交价必须是真实报价、权重和为 1）， 并用 WORK503_ASSERT_VIOLATION=1 故意触发过一次，断言原文见交付评论。

8失败项、限制与翻案条件

8.1 已知限制

  • 算力约束：本机无 GPU，训练段缩到 2015–2019（论文 2009–2019）、每阶段 ≤6 轮（论文 ≤50）。 这会让所有档的绝对指标系统性低于论文，但对四档之间的相对差（Δ_drop）影响较小，因为四档共享同一协议与种子。
  • 先验因子替换：JKP 13 个全球因子没有 A 股个股级对应值，本单自建 6 个先验，因此 no_prior 档的降幅大概率小于论文的 −15.2%， 这一项不能用来支持「码本有效」的结论。
  • 数据底座：Qlib 官方 cn_data 只到 2020-09-25 且无 $vwap，覆盖不到测试期，故自建快照（新浪 + baostock PIT 名单）。
  • 涨跌停口径：没有逐日历史 ST 标记，本单按「板块限 ∪ ST 5%」的保守并集判定，代价是非 ST 股当日恰好 ±5% 会被误掩码（只会削弱收益，不会虚增）。
  • 标签口径冲突：论文正文写 open(t+1)→close(t+k)，上游仓库的 yaml 用 close→close；本单以正文为准，两份都写在预注册 §1.1 D3。
  • 主检验量的符号口径：派单卡写 Δ_ic=(RankIC_full−RankIC_no_vq)/RankIC_full，但同时写「论文基准 −26.9%」与进带 [−40%,−15%]——这三句互相矛盾（按字面公式代入论文数字得 +26.9%，落不进进带）。 本单按预注册 v1.4 冻结：判词量取 Δ_drop=(RankIC_no_vq−RankIC_full)/RankIC_full，判词带逐字不动，并列报告字面式的 Δ_formula。 这个修订在正式结果产生之前完成（当时正式训练尚未跑完），且进/退两带的数字一次都没变过；单测 scripts/work503_test_verdict.py 固化了两种自洽读法等价、与字面读法的分歧区间。 详见预注册 v1.3 / v1.4 与失败记录 §7.2。
  • 独立复算脚本不是纯标准库：audit/README.md 规则 2 要求只用标准库，但预测快照是 parquet，标准库没有 parquet 读取器， 因此用了 numpy / pandas / scipy（仅用于读快照与算 spearman）；组合与指标全部由该脚本自己的字典 + 显式账本实现重算，与建模侧不共用任何函数。 这一点写进了产物 audit_recompute.json 的 independence 字段，不靠口头声明。
  • 独立性自检是弱自检：independence_selfcheck() 用 ast 扫本文件的 import，能证明「没有 import 建模函数」， 但证明不了「没有把建模逻辑抄一遍」——后者靠人工代码走查与两套实现的人工对照。

8.2 失败实验与被排除的路径

  • 训练前的数据完整性审计发现并修复了 5 处数据构造层缺陷（Qlib 二进制日历错位、样本索引日历错位、新股规则未落地、复牌日涨跌停漏判、元数据年份错写）； 修复前的一切产物已作废，不进本报告。
  • 第一轮 stage-1 训练因上游 wandb.log 未初始化而崩溃，改为显式初始化后重跑（见交付评论的训练日志）。
  • 第二轮 stage-1 作废：训练没按种子初始化全局 RNG，模型初始化与批次打乱用的是未播种的随机源，「种子 42 / 2024」只是给两次抽样贴标签；改为按上游 stage2.py 的做法在建模前播种。
  • 独立代码审查（子代理，按《代码审查规范》分级）报出 2 条 blocking：判词带与公式的符号矛盾（→ 预注册 v1.3 / v1.4，见 §8.1）、判定脚本在 H3 处必崩（sr_stat 不接受 axis）。两条都在正式结果产生之前修完，并补了边界单测。
  • 审查同时暴露了本单自己的一处错误论证：预注册 v1.3 §4 声称「两种符号口径给出的判词逐点相同」，实际不相等（进带取负是 [15%,40%]，不是同一个集合）。 该错误由落盘后立刻补的边界单测当场判红（121 个网格点只有 71 个成立），在正式训练未跑完、无任何正式结果可见的时点更正为 v1.4 的正确论证。

8.3 翻案条件

  • 若在论文口径的训练段（2009–2019）、论文轮数（≤50）、13 个 JKP 先验下重跑，Δ_ic 回到 [−40%, −15%]，则本单结论应翻案为「条件性成立」。
  • 若把涨跌停掩码改为「只用板块限、不并 ST 5%」后 Δ_ic 明显移动，则说明本单结论对掩码口径敏感，结论强度应下调。
  • 若增加种子数（论文 5 个）后 Δ_ic 的种子间离散度变大，则「中位数」这个统计量本身不足以支撑进/退判词。
