6沉默失败清单：这一轮真正丢的东西

  1. 四档 0/8：两次共 8 个进程在 15–30 s 内退出，但训练驱动把它们记成「失败后继续」，日志里没有聚合告警； 真正的信号是 run_all.log 最后一行 chain exit rc=1。
  2. 后处理链在第 1 步就断：finish_summary.json 的 backtest_validation.ok=false， 原因是一个 编码问题（GBK 控制台写出的 JSON 被按 UTF-8 读）而不是数据问题 —— backtest_results.json 本身是好的，只跑了 gru_s2024 一格。
  3. GRU s42 被墙钟退化杀掉：同一 epoch 从 73 s 退化到 ≈800 s（epoch 33→42）， 另有 1 次 CUDA error: an illegal memory access。这台机器的墙钟不稳定， 任何「实测 s/epoch × 轮数」的计划都要留 2× 余量。
  4. num_workers=8 在这台机器上不可靠：2026-11-27 三次尝试里 2 次硬退（RC=127，无 traceback）、 1 次成功但 spawn 用掉 121 s；num_workers=2 同一配置 10 轮连跑稳定。 11-25 那轮 GRU 的「epoch 73 s → 800 s 退化」与 1 次 CUDA illegal memory access， 方向上也与 8 worker 争抢一致。
  5. 共享 Python 环境在 11-26 07:56 被损坏：F:\001_install\020_Anaconda\envs\ds 里 73 个分布有文件缺失（typing_extensions.py、packaging/specifiers.py 等）， 导致 import torch 直接失败。已在本单 .venv/ 里按原版本重装 73 个包修复 （不动共享环境），取证脚本 experiments/WORK-557/_env_damage_scan.py。 这条影响所有用该环境的任务，不只本单。
